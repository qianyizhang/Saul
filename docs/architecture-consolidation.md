# Architecture consolidation

## Baseline and accepted scope

At `e741632`, a Call batch and an EZ lookup can run through the same signed
credential owner. Each helper request starts in a separate process. Replacing
the key between requests can affect an active batch. The accepted
[coordination decision](adr/0008-coordinate-shared-connection-work.md) defines
the admission, recovery and compatibility work. A dedicated Stop prompt is
deferred. The existing Stop action is sufficient.

The baseline has 750 tracked files and about 4.8 MB of Git blob content.
An inventory of static relative imports and literal dynamic imports among 251
Saul implementation files found 814 distinct edges including type references.
The only multi-file strongly connected group in that inventory was
`configuration/connections.ts` and `configuration/definition.ts`. At the
feature level there are additional dependencies in both directions between
Calls and Annotations. These counts describe the source tree at the baseline.

The [native package](../native/credentials/Package.swift) exposes the system
CSQLite module to EZ and the coordination implementation. Public settings
values, credential transport, coordination and the signed executable have
distinct targets. Existing extension, host and bundle identities remain the
installation and data boundaries.

At `4cf42ec`, the same import scan found 260 Saul implementation files and 868
distinct edges. All six prohibited baseline edges were removed. Calls imports
neither Annotations nor Reading internals. Annotations consumes Custom Actions
and Configuration has no dependency on Reading. One two-file group remains
when type references are included: configuration/definition and connections.
Its return edge imports types only. The [runtime boundary probes](../apps/saul/tests/runtime-boundaries.test.mts)
exercise the enforced directions.

Older clients and interrupted setups still constrain pruning. Both runtime
adapters read legacy single-record setup data, and the Custom Actions store
still migrates the previous Chrome choice format. History receipts retain the
original wire identity for reconnect. The installed helper identities, common
settings scope names and shared schema stay stable. See the [credential
compatibility limits](../contracts/credentials.md#shared-connection-setup-and-execution)
and [History receipt rules](../contracts/history.md#accepted-interface).

Through `4cf42ec`, tracked files grew from 750 to 770 and Git blob content grew
by about 176 KB. The additional implementation covers cross-process exclusion,
per-connection recovery, error handling and tests. The reduction is in duplicated
operation targeting, mutable attempt state and feature dependencies. A dedicated
prompt to stop another app’s batch remains deferred. The existing Stop control
and a retry after the operation ends cover that case.

The native checks used private temporary directories, disposable settings and
History databases, synthetic credentials and local callback fixtures. The
extension checks used isolated Chromium profiles. Personal installs, provider
accounts and production data require separate acceptance.
